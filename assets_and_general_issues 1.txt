8) Equity :

Equity – Add Asset Screen Changes

Remove the Invested Amount and Current Value input fields, as Average Purchase Price Per Share and Quantity / Shares Held are already available. Invested Amount should be automatically calculated using Quantity × Average Purchase Price, while Current Value should be fetched using market data APIs. Add an optional SIP Enabled checkbox and display the Monthly SIP Amount field only when SIP is enabled.

Equity – Edit Asset Screen Changes

Remove the editable Invested Amount and Current Value fields. Allow users to edit only Quantity / Shares Held, Average Purchase Price Per Share, Investment Date, SIP Enabled status, Monthly SIP Amount, and Notes. Users should be able to enable, disable, pause, or modify the SIP amount. When SIP is active, display "SIP ₹X/mo" in the asset table. If no SIP was ever configured, display "Lump Sum". If a previously active SIP is disabled, display "SIP Paused".

9) Real Estate : 

Real Estate – Edit Asset Screen Changes

Remove the Quantity field entirely, as quantity is not relevant for real estate assets. Replace the current Edit Asset screen with editable fields for Property Name, Area (sq. ft.), Location / Address, Current Value (₹), Purchase Date, and Notes. The Purchase Price (Invested Amount) should remain read-only because it represents the original acquisition cost, while Current Value should remain editable so users can periodically update the property's estimated market value. This allows Profit/Loss and portfolio metrics to be recalculated automatically whenever the property valuation changes.

10) Physical Gold : 

Physical Gold – Add Asset Screen Changes

The current Add Asset screen should be updated to include a Photo Upload / Camera Capture feature, as documenting physical assets through photographs is a mandatory project requirement. The Invested Amount field should be removed because it can be automatically calculated using Weight (grams) × Buy Price Per Gram. However, the Current Value field should remain as a user input because the actual value of jewellery depends on factors such as making charges, resale value, gemstones, and jeweller-specific pricing, which cannot be accurately determined using a standard gold-rate API. The final Add Asset screen should collect Asset Name, Weight (grams), Purity, Buy Price Per Gram, Current Estimated Value, Purchase Date, Photo Upload / Camera Capture, and Notes.

Physical Gold – Edit Asset Screen Changes

The current Edit Asset screen should be redesigned to remove the generic Quantity and Invested Amount fields. Instead, users should be able to edit Weight (grams), Purity, Buy Price Per Gram, Current Estimated Value, Purchase Date, Asset Photos, and Notes. Any change to the weight, purity, purchase price, or current estimated value should automatically refresh the portfolio metrics. Asset photographs should also be editable so that users can add, replace, or remove jewellery images whenever required.


11) Digital Gold : 

Digital Gold – Add Asset Screen Changes

The current Add Asset screen should be updated to remove the Invested Amount and Current Value input fields, as both values can be calculated automatically. Since Digital Gold supports recurring investments, an optional SIP Enabled checkbox should be added. When SIP is enabled, a Monthly SIP Amount field should be displayed. The system should automatically calculate Invested Amount using Quantity × Buy Price Per Gram and estimate the Current Value using the latest gold rate retrieved from a market data source.

Digital Gold – Edit Asset Screen Changes

12) Sovereign Gold Bond :

Sovereign Gold Bond – Add Asset Screen Changes

The current Add Asset screen should be updated to remove the Invested Amount and Current Value input fields, as both values can be calculated automatically. The form should collect Bond Name, ISIN Code (Optional), NSE/BSE Ticker (Optional), Bonds Held (Units), Issue Price (₹/Bond), Issue / Purchase Date, Coupon Rate (%), Maturity Date, and Notes. The system should automatically calculate the Invested Amount using Bonds Held × Issue Price, while the Current Value should be derived using the latest market price of the Sovereign Gold Bond fetched from a market data source.

Sovereign Gold Bond – Edit Asset Screen Changes

The current Edit Asset screen should be updated to remove the editable Invested Amount and Current Value fields. Users should instead be able to edit Bonds Held (Units), Issue Price (₹/Bond), Issue / Purchase Date, Maturity Date, Coupon Rate (%), and Notes. Any changes to the bond quantity or issue price should automatically recalculate the Invested Amount, while the Current Value should continue to be derived from the latest market price retrieved through market data APIs. The Bond Name, ISIN Code, and NSE/BSE Ticker should remain unchanged after asset creation, as they uniquely identify the Sovereign Gold Bond series.

15) Date Validation Requirements

Asset Date Validation - 
For asset acquisition dates such as Investment Date, Purchase Date, Issue Date, Start Date, and Account Opening Date, users should not be allowed to select a date later than the current system date. The current date should be permitted, as users may add assets on the same day they were purchased or created.

Maturity Date Validation -
For assets that contain a maturity period, such as Fixed Deposits and Sovereign Gold Bonds, the Maturity Date must be later than the corresponding Start Date, Issue Date, or Purchase Date. Future maturity dates should be allowed, as they represent the scheduled completion date of the investment.

Date of Birth Validation -
During user registration, the Date of Birth must be earlier than the current system date. Users should not be allowed to select today's date or any future date.


16) Asset Details Screen Requirement - 
For all asset types, selecting an asset from the asset table should open the corresponding Asset Details screen. This screen should display all information associated with the selected asset, including all user-entered fields, asset-specific details, uploaded documents or images (where applicable), and system-calculated values such as current valuation, invested amount, profit/loss, and performance metrics.

17) Dynamic Benchmark Allocation Requirement :

The Current vs Recommended Allocation chart in the Assets page should use dynamic benchmark allocations instead of fixed percentages. During user registration, the system should determine the investor profile based on the user's age and automatically classify the user as Conservative, Moderate, or Aggressive. Based on the assigned profile, the application should apply a predefined benchmark allocation model and compare the user's actual portfolio allocation against the recommended allocation. The benchmark should be recalculated whenever the user's profile changes, ensuring that portfolio recommendations remain relevant throughout different stages of the user's investment journey.
